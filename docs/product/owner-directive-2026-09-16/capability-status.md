The baseline recorded here was the repository at protected develop `2c573a24`, measured 2026-09-16.

**Re-derived 2026-09-18 against protected develop `5b2c7840`**, after the six directive pull requests
merged (#410 gates, #411 environment, #412 search, #413 organisation administration, #414 platform
console, #415 inventory, #416 alerts). Every row below was checked against that head: its status, its
actual UI route, the backend operation the screen calls, and what the evidence for it is.

## The four states

- **implemented** — a user can reach the capability through a route in the web application, the
  route calls a backend operation that exists, and the evidence column names where that was
  demonstrated. Where an operation exists and works but has no screen, the row says
  `implemented (API only)` and is not a completed workflow.
- **partial** — some of the capability exists and a stated part of it does not. The gap is written
  in the row, not left to be inferred.
- **missing** — no route, no operation, or neither.
- **externally blocked** — the capability cannot be completed inside this repository, and the
  reason names what is outside it.

A row needs all three of a UI route, a backend operation and evidence before it reads
**implemented**. A plan is not evidence. An API without its screen is not a completed workflow. A
screenshot of a screen that performed no transaction is not evidence that the transaction works.

## What the evidence column says at this revision, and what it does not

**Read this before reading any row.** The re-derivation of 2026-09-18 was a **code reading**: for
each row, the route file, the screen, the adapter and the backend operation were opened and read at
`5b2c7840`. That is what the evidence column reports, and it is enough to tell you that a screen
exists, which operation it calls, and what it refuses.

**It is not a demonstration that the workflow runs.** Two proofs are owed for the work these six
pull requests merged, and neither has been taken:

| Owed proof                              | What it would establish                                                                                                            |
| --------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------- |
| **Authenticated console browser walk**  | That a signed-in platform owner can open every console screen and complete a transaction on it.                                    |
| **Acceptance journey for the new work** | That the inventory, organisation-administration, search and alert capabilities run end to end over the service against a database. |

Every row whose proof depends on one of them carries **`proof owed`** and names which. A row marked
`proof owed` is **not** a claim that the capability was demonstrated; it is a claim that the code
implementing it was read. No hosted run, acceptance run, certification or approval is claimed
anywhere in this file.
