# P1-20 open decisions and accepted limitations

Every item here is a place where the protected schema, or the absence of an approved
decision, stops P1-20 from doing what the phase prose describes. None is a defect
being reclassified; each says what does not exist and what was done instead.

## Accepted limitations

| Id           | Severity | Statement                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| ------------ | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| `P1-20-A-01` | Low      | **Branch service availability has no effective period.** `svc.branch_service_availability` carries `is_available` and `status` and no dates, and `uq_branch_service_availability_service` makes exactly one row per `(tenant, company, branch, service)` where not deleted — so overlap is structurally impossible and there is nothing to schedule. The phase prose's "effective period" and "overlap constraints" do not exist. Availability is a single current row, and no application-only date range was fabricated to simulate one.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `P1-20-A-02` | Low      | **Standard labour time has no branch override.** `svc.standard_labor_times` hangs off `service_version_id` only. Labour time is per service version for the whole tenant. No branch column was invented.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| `P1-20-A-03` | Low      | **`decided_by` is the recording staff user, not the customer.** `quo.approval_decisions.decided_by` is `iam.current_user_id()`, and the schema has no customer-principal column. The integrity control is that a claimed `decidingPartyRef` must equal the quotation's `payer_partner_ref`; the recorded fact is truthfully "staff user X recorded that the payer decided Y over channel Z". Stated rather than dressed up as a customer signature.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `P1-20-A-04` | Low      | **Three service-catalog audit actions have no producer yet.** `svc.service.updated`, `svc.branch_availability.changed` and `svc.service_version.published` are registered but unused: this phase ships the catalog READ surface, and the protected requirements mandate no public mutation. Registered now so a later phase cannot invent a conflicting code for the same fact. No operation declares them, so the inventory gate correctly does not report them.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                   |
| `P1-20-A-05` | Low      | **Expiration has no scheduler.** `QuotationService.expireLapsed` is bounded, idempotent and database-clock-based, but nothing calls it periodically. No production scheduling infrastructure is provisioned (ADR-012 — no environment beyond Local is approved), and inventing one would be fabrication. The method is the contract a scheduler will call.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                          |
| `P1-20-A-06` | Low      | **No alert routing.** The signals an alert should consume are named in `devops-observability.md`, and they are emitted. There is no provisioned destination to route them to, so a routing rule written now could not be tested and would be an unverifiable claim.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                 |
| `P1-20-A-07` | Low      | **The price-ambiguity guard is unreachable.** `PriceResolutionService` refuses with `ERR-CON-001` when two rules tie on specificity and priority. `uq_price_rules_signature` makes that state impossible: a specificity score determines exactly which of company/branch/class are non-null, and the resolver forces each non-null column to equal the query value, so a tie implies an identical signature the index refuses. The guard is retained because it defends a property resting on that index continuing to exist — drop or widen the index and resolution silently becomes an `id`-ordered coin flip on a customer's price — and the test asserts the structural guarantee instead of pretending the branch has a positive case. A review noted the cost fairly: `countTiedPriceRules` mirrors roughly 45 lines of `svc.resolve_price` precedence SQL (assignment filter, the 4/2/1 specificity expression, ordering, version and rule filters) with no test comparing the two, so a future change to the protected function desynchronises it silently. Accepted for one indexed COUNT per resolution. |
| `P1-20-A-08` | Low      | **Public price-list reads are bounded by a limit, not paged.** `GET /api/v1/price-lists` returns up to 100 lists with no cursor. A tenant with more than that cannot see the remainder through this endpoint. Accepted for this phase because a price list is administrative reference data whose realistic cardinality is small; a keyset page can be added without a contract change.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| `P1-20-A-09` | Low      | **Three module cycles are live and no gate refuses them.** `work-order` ↔ `diagnostics`, ↔ `quality` and ↔ `technician` each import the other's public surface. All three are present at the P1-19 gate SHA `0d86a19`; **P1-20 introduced none** — `CommercialApprovalReader` exists precisely so this phase would not add a fourth. The defect is that `scripts/check-module-boundaries.mjs` enforces B1 and B3–B12 with no cycle rule, so `validate:module-boundaries` prints OK with all three present, and `composeModule`'s memoised laziness means a cycle surfaces only as a partially-initialised module under a particular import order. A B13 rule now would fail the build on another phase's debt, so it is recorded rather than added, and the false comment in `commercial-approval.ts` claiming mutual imports are "the shape this repository avoids" has been removed.                                                                                                                                                                                                                              |

## Open decisions — deliberately not decided here

These are commercial policy questions with no protected answer. In each case P1-20
implements only decision-neutral infrastructure and records the gap rather than
picking a default.

| Question                                    | Why it is not answered                                                                                                                                                                                                                                                                              | What was implemented                                                                                                                                                   |
| ------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Rounding mode and stage**                 | Already answered by the schema, so it is NOT open: `ck_quotation_items_tax_amount` and `ck_quotation_items_line_total` fix `round(…, 4)` per line, discount before tax, tax exclusive; document totals are pure sums. Listed so a reader does not go looking for a decision that was made in P1-10. | The exact protected expressions, computed in SQL                                                                                                                       |
| **Currency minor units**                    | `shared.currencies.minor_unit` exists (USD 2, JOD 3) but no protected rule says a quotation must round to it, and the money columns are `numeric(18,4)` regardless. Choosing one would invent a display or rounding policy.                                                                         | Amounts are stored and returned at the column's scale; no minor-unit rounding is applied anywhere                                                                      |
| **Tax jurisdiction defaults**               | Nothing in the catalog names a country, region or statutory rate. `org.tax_rates` is per company and per tax class, configured by an operator.                                                                                                                                                      | A service whose price rule names a tax class with no effective rate is a hard refusal, never an untaxed line. No rate is hard-coded, and Jordan is nowhere in the code |
| **Payment terms**                           | No approved terms exist and no column holds them.                                                                                                                                                                                                                                                   | Not modelled                                                                                                                                                           |
| **Currency conversion**                     | Out of scope for Phase 1 and unrepresentable: no rate table exists.                                                                                                                                                                                                                                 | `Money` exposes no conversion method at all, so silent FX is unexpressible rather than discouraged. A cross-currency comparison is a deterministic failure             |
| **Quotation validity default**              | `quo.quotation_revisions.expires_at` is nullable and no protected rule supplies a default period.                                                                                                                                                                                                   | `expiresAt` is optional at issue; a revision with none never lapses. No default was invented                                                                           |
| **Whether a quotation may be standalone**   | Not open — `quo.quotations.work_order_id` is NOT NULL.                                                                                                                                                                                                                                              | Every quotation belongs to a work order                                                                                                                                |
| **Retention policy for quotation evidence** | Governed by `shared.retention_classes`, which is operator-configured reference data.                                                                                                                                                                                                                | Evidence uses the existing document lifecycle; no retention default is set by this phase                                                                               |

## Risks

| Risk                                                                      | Standing after P1-20                                                                                                                                                                                                                                                                                                                                                   |
| ------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **RSK-24** — financial calculation drift between application and database | **Mitigated.** PostgreSQL is the only calculation engine; `insertItem` writes the CHECK constraints' own expressions with each parameter cast to its column's precision and scale, so the engine and the validator cannot disagree. `Decimal` performs no authoritative arithmetic and 32 unit tests pin values IEEE-754 gets wrong.                                   |
| **RSK-25** — commercial data exposed beyond its audience                  | **Mitigated.** The catalog read carries no price and that is asserted by scanning the whole response body; `svc.price.read` is `medium` risk; every branch-scoped read is authorized against a concrete target, including the case where the caller's grant union already contains the branch.                                                                         |
| **RSK-26** — a customer charged for work they did not approve             | **Mitigated.** Decisions are per item and the first decision on a line is final; `presentedRevisionId` prevents approving a revision the client did not read; any rejected line makes the quotation rejected; the additional-work link refuses a superseded, draft, expired, rejected or undecided revision, and refuses one belonging to another work order or scope. |
| **RSK-27** — an issued quotation changing after presentation              | **Mitigated.** `quo.guard_quotation_item` refuses item writes on a non-draft parent and `quo.guard_quotation_revision_freeze` freezes captured totals. Proven by republishing the price list at five times the amount after issue and asserting the stored columns for that revision do not move.                                                                      |
