# P1-29 screen-to-contract matrix

**Purpose: prove that P1-29 has no hidden backend dependency left.** Every UI action a P1-29 screen
could offer is mapped to a real operation, a real permission code, and — where one is missing — the
`BR-` slice that supplies it.

No screen is implemented or authorised by this document.

**Readiness vocabulary**

|             |                                                                                      |
| ----------- | ------------------------------------------------------------------------------------ |
| **READY**   | the operation exists on `develop` today; the screen is buildable now                 |
| **BR-0N**   | blocked until that slice closes                                                      |
| **REFUSED** | the capability is not buildable and no slice supplies it — the honest scope boundary |
| **OWNER**   | blocked on an Owner decision, not on code                                            |

### The 24 REFUSED actions are the phase's honest scope boundary

They cannot be built, and **no amount of client work changes that**. Each is recorded against its
finding so that a future phase can pick it up, and so that no P1-29 screen quietly implies a
capability the platform does not have.

**Six of them are traps rather than absences** — cases where a screen _could_ be built and would be
lying: W18 (closure implies parts settled), W19 (a constant rendered as information), D12
(evidence rendered as item-bound), D16 (a severity roll-up that does not exist), H6 (a merged
timeline claimed complete), and H7 (an invented actor name).

**Conclusion: P1-29 has no hidden backend dependency.** Every action is READY, owned by a named
slice, awaiting a named Owner decision, or explicitly refused with its evidence.
