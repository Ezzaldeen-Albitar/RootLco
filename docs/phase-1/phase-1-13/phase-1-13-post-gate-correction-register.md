### ADV-04 — idempotency replay ownership not bound to the principal

| Field                      | Detail                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                    |
| -------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| **Finding**                | Replay identity was `(tenant, operation, key)` and the fingerprint covered method, path and body only. Two users of one tenant issuing the same request with the same key were indistinguishable, so the second received the first's stored response document.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                            |
| **Affected files**         | `src/server/http/idempotency.ts`, `src/server/http/route-handler.ts`                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                      |
| **Evidence of the defect** | The stored row was matched on tenant + operation + key, and the fingerprint comparison could not separate two principals because no principal was in the fingerprint.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                     |
| **Correction**             | `requestFingerprint` now takes the frozen `RequestContext` and binds tenant + principal into a length-prefixed, scheme-versioned SHA-256 preimage. Taking the whole context is deliberate: there is no parameter through which a request body could supply an identity, so spoofing is prevented by the shape of the API. It fails closed with `ERR-IAM-002` when no principal is resolved. A different principal therefore fails the fingerprint comparison and receives the **same** `ERR-INT-001` as an ordinary payload mismatch — no oracle. The distinction is recorded server-side only, with correlation ID and `principal-mismatch` / `payload-mismatch`, and without the key, either fingerprint, the stored response, or the owner's identity. |
| **Regression test**        | `tests/backend/idempotency.test.ts` — the ten required proofs, including: same principal replays; different payload rejected; **different principal in the same tenant rejected with no disclosure**, asserted by checking that the serialized failure contains neither the stored value, nor the owner's id, nor the key, nor the fingerprint, and that its code and message are identical to a payload conflict; cross-tenant isolation; concurrent first use by two different principals resolving to `ERR-INT-001` rather than a shared result; a forged body identity field failing to influence the binding; and an unresolved principal failing closed.                                                                                            |
| **Database change**        | **None.** `request_fingerprint` is `text NOT NULL` with no length constraint and `created_by uuid NOT NULL` already stores the actor, so the frozen schema carries the fix unchanged. No migration was added, and the unique constraint `(tenant_id, operation, idempotency_key)` is untouched.                                                                                                                                                                                                                                                                                                                                                                                                                                                           |
| **Conclusion impact**      | **Changes a conclusion.** The gate described idempotency as delivered; it was, but its replay identity was weaker than a reader would assume. Latent in P1-13 — no idempotent business command existed — and live from P1-14.                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                             |
| **Disposition**            | **CLOSED.**                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                                               |

## 3. Adversarial review of this corrective work

Sixteen attack vectors, run against the corrective branch itself. Everything in the boundary half was
**executed** against the real checker with throwaway fixture trees; the idempotency half is a mix of
executed probes and code reading, marked per row.

An attempt to delegate this review to parallel agents failed outright — all sixteen hit a session
limit and returned nothing. The review below was therefore performed directly, and is recorded as
such rather than presented as a broader sweep than it was.

### 3.1 Findings

Two real bypasses were found in the first version of the ADV-01 fix. Both were fixed, and both now
have regression tests.

| ID       | Severity | Finding                                                                                                                                                                                                                                                             | Evidence                                                                                  | Remediation                                                                                                                         | Regression test                                                                  | Disposition |
| -------- | -------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- | ----------- |
| ADV-H-01 | Medium   | **Symlink laundering.** Canonical resolution is lexical, so a symlink inside the tree defeats it: with `app/api/shortcut -> server/db`, a handler importing `../shortcut/transaction` canonicalises to `app/api/shortcut/transaction` and matches no layering rule. | Executed: fixture with a real directory symlink, checker exited **0** with no rule fired. | New rule **B10** refuses any symlink in the scanned tree. `walk()` uses `lstatSync`, which reports the link rather than its target. | "refuses a symlink in the source tree, which would launder a prohibited target"  | **FIXED**   |
| ADV-H-02 | Medium   | **Case-varied bypass.** Rules matched lower-case prefixes, so `../../../../Server/DB/Transaction` matched nothing — and on Windows and macOS, whose filesystems are case-insensitive, that import resolves to the real file.                                        | Executed: fixture with upper-cased segments, checker exited **0** with no rule fired.     | `canonicalise()` lower-cases the target, and the file path is case-folded for rule matching. Repeated separators are collapsed too. | "applies the rules case-insensitively, so a case-varied path cannot bypass them" | **FIXED**   |

**`validate:canonical-docs` exits 1 in the clean room, and that is correct.** It verifies the
SHA-256 of the two canonical Word documents, which by owner decision live _outside_ the repository
at `../RootLco_Phase_1_Development_Plan_recovered_v01.docx` and
`../documentation/RootLco_Master_Project_Documentation.docx`. A clone in a temporary directory has
no such siblings, so the check reports `MISSING or unreadable` for both. It passes in the working
tree, where the documents exist. It is **not** part of hosted CI, which could not reach them either.
Environmental, not a defect in this change.

**`test:db` reported `1 failed | 1183 passed` on the first clean-room pass and `1184 passed` on an
isolated re-run.** The failing test's identity was not captured before the process exited, so it
cannot be named — the same gap recorded at the P1-13 gate, and the second time this signature has
appeared. What is different this time is a candidate mechanism: that first pass ran `test`,
`test:backend` and `test:db` back to back in one script against the **same** database, and
`test:backend` holds its own pools and fixtures. The isolated re-run of `test:db` alone was fully
green. Hosted CI runs the database suite in its own job with its own PostgreSQL service container,
so the suites never share a database there.

This is stated as a suspected mechanism, not a diagnosis. It is not claimed to be fixed.
