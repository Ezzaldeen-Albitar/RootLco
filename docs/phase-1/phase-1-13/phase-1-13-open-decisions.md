# Phase 1-13 — Open Decisions

**Phase:** P1-13 — Backend Architecture and Shared Application Foundation ·
**Date:** 2026-07-21 · **Owner:** Eng. Ezzaldeen Al-Bitar.

Decisions the phase deliberately did **not** make. Each is recorded rather than guessed; the
foundation is built so that resolving any of them is a configuration or adapter change, not a
redesign.

| Ref                              | Decision                                                                 | Why P1-13 did not decide it                                                                                                  | How the foundation stays neutral                                                                                                                                                                                                     |
| -------------------------------- | ------------------------------------------------------------------------ | ---------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| **P1-OD-027** (NFR-SCL)          | Production capacity, throughput, latency and scale targets               | Unresolved from P1-12; no production environment and no load evidence exist                                                  | Every numeric limit (pool size, batch size, rate limits, TTLs, backoff bounds) is configuration with a bounded default, labelled a **proposed validation baseline**                                                                  |
| **OIR-01**                       | Product name                                                             | Owner approval pending (ADR-011)                                                                                             | No product name appears in a package name, header, OpenAPI document, or template; the placeholder constant is used                                                                                                                   |
| **P1-OD-041**                    | Release-group naming and grouping approval                               | Owner approval pending                                                                                                       | Grouping affects documentation labels only; no code depends on it                                                                                                                                                                    |
| **AUTH-PROVIDER**                | The authentication provider and session-claims format                    | Phase 1-14 owns authentication and its provider decision                                                                     | `SessionAuthenticator` is a port; the default fails closed with `ERR-IAM-002`; the claims contract is fixed (`identityProvider`, `providerSubject`, `tenantId`) and the tenant claim is verified against the database, never trusted |
| **MONITORING-PLATFORM**          | Error-monitoring platform and DSN handling                               | No environment beyond Local (ADR-012); a repository must not hold a production DSN                                           | `ErrorMonitor` is a port receiving an already-sanitised event; the default records and logs. A Sentry-or-equivalent adapter is deployment composition                                                                                |
| **METRICS-BACKEND**              | Metrics exporter and storage                                             | Same as above                                                                                                                | `MetricsRecorder` is a port with a fixed instrument vocabulary; the default is in-memory and bounded                                                                                                                                 |
| **DISTRIBUTED-CACHE**            | Whether a shared cache service is adopted                                | Introducing one now would add an operational dependency and a second place tenant data lives, for no current benefit         | `Cache` is a port; `DistributedCache` is the contract a future adapter implements; keys are already tenant-safe and versioned                                                                                                        |
| **DISTRIBUTED-RATE-LIMIT-STORE** | The shared store backing multi-instance rate limiting                    | Depends on the deployment topology decision                                                                                  | `RateLimitStore` is a port; `assertStoreSuitableForMultiInstance()` refuses to let a process-local store be treated as a distributed one                                                                                             |
| **REPLICA-TOPOLOGY**             | Whether read replicas are introduced, and which reads are stale-tolerant | Requires a provisioned replica and observable replication lag first (ADR-017)                                                | `poolFor('replica')` returns the primary and records why; no read is silently routed                                                                                                                                                 |
| **BROKER**                       | Whether an external message broker replaces or fronts the outbox         | The database outbox is proven and sufficient at this stage; a broker would add an unproven delivery path beside a proven one | Consumers are registered against an interface, not a transport; the outbox remains the source of truth (ADR-014)                                                                                                                     |
| **DBCR-P1-13-001**               | Granting the runtime archetype its four write capabilities               | P1-13 must not add or modify a migration                                                                                     | Capability is measured at runtime and the foundation fails closed; when the grant is applied the preflight turns green with no code change                                                                                           |

## Rule applied throughout

Where a decision was open, the phase chose the option that is **reversible and fails closed** over
the option that is convenient and fails open. A port with a refusing default can be replaced by an
adapter; a hard-coded provider, a trusted forwarded header, or a silently-skipped audit record
cannot be un-shipped.
