# P1-31 error-path matrix

One row per P1-31 operation, one column per refusal the platform contract publishes.
A cell carries the file and line of the case that covers it, or the word "not applicable"
with the reason. No cell says "covered" without a line.

## How to read the columns

- **403** — the authority refusal. Every one of the 45 is covered by the same derived `it.each`, `tests/backend/p1-31-privilege-escalation.test.ts:1807`, whose case name is `SE-5 <operation id>`. The table does not repeat the citation per row.
- **422** — an invalid request BODY, refused by the boundary schema before anything is written. A read carries no body, so the cell is "not applicable" unless the read validates a path parameter or a query value, in which case that case is cited instead.
- **428 `ERR-CON-002`** — a version-guarded write with no `If-Match`. Only the 11 operations declaring `versionGuarded: true` have one.
- **409 `ERR-CON-001`** — a version-guarded write carrying a stale `If-Match`. Same 11.
- **replay same-key** — an identical retry under one `Idempotency-Key` answered with the stored document and executing nothing. Only the 16 operations declaring `idempotent: true` have one.
- **replay different-body `ERR-INT-001`** — the SAME key offered with a different body, refused. The half a replay case cannot assert: a route storing the key alone passes the replay case and answers a second, different request with the first one's document.
- **cross-tenant** — a foreign tenant addressing this tenant's rows. Covered for 40 operations by `tests/backend/p1-31-privilege-escalation.test.ts:2040` (case name `SE-6 <operation id>`); the five that name no row and no scope carry the reason instead, and the reason list is itself asserted at `tests/backend/p1-31-privilege-escalation.test.ts:1660`.
- **isolation (RLS)** — the DATABASE-layer proof that the row is hidden from another tenant, independent of the application. The structural half (RLS enabled and forced, a tenant-scoped SELECT and INSERT policy, a refused cross-tenant INSERT) is auto-enumerated over every `sal`, `wty` and `rpt` table by `tests/db/p1-11-isolation.test.ts:58` and `:97`, and over every module schema by `tests/db/shared-hardening.test.ts:329`. The cell names the BEHAVIOURAL read negative for the table the operation addresses.
