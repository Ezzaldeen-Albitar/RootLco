## 1. What this matrix is

This matrix enumerates **every requirement of OWASP ASVS v5.0.0** (fetched from the pinned
upstream release tag `v5.0.0` of `github.com/OWASP/ASVS` on 2026-07-17) and records, per
requirement, its applicability to this product, its verification status, and the evidence
behind any verified claim. The verification target is defined in
[security-baseline.md](./security-baseline.md): **Level 2 as the general baseline**, with
Level 3 applied selectively to the named high-risk workflows.

> **This matrix is a tracking instrument, not a compliance claim.** No OWASP
> compliance, certification, or attestation is claimed — see
> [SECURITY.md §9](../../SECURITY.md) and the baseline’s explicit non-claim.

**Requirement summaries are paraphrases**, kept deliberately short. The authoritative
requirement text is the pinned upstream release (CC BY-SA 4.0, © OWASP Foundation); consult
it before implementing against any row.

## 2. How to read a row

| Column                           | Meaning                                                                                                                                                                                                                                                                                                     |
| -------------------------------- | ----------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| ASVS ID / L                      | The upstream requirement ID and its ASVS level (1, 2 or 3).                                                                                                                                                                                                                                                 |
| Requirement focus                | A paraphrase — never the upstream text. In this first revision the focus is written at **section granularity** (all rows of a section share the section-focus summary) except where a row was judged individually; the owning phase replaces it with a per-requirement paraphrase when it picks the row up. |
| Applicability                    | Whether the requirement is in the RootLco baseline, selected L3, out-of-baseline L3, or not applicable (with justification).                                                                                                                                                                                |
| Risk                             | Critical / High / Medium / Low, judged for a multi-tenant automotive CRM/ERP holding financial data.                                                                                                                                                                                                        |
| RootLco ID                       | Deterministic: `RL-ASVS-<ASVS ID>`.                                                                                                                                                                                                                                                                         |
| Owning phase / Module            | Where the control lands, per the phase map in [security-baseline.md](./security-baseline.md). Ranges are used until the owning phase instruction is issued.                                                                                                                                                 |
| Implementation / Test / Evidence | Real artifact paths, or “—” until the owning phase assigns them.                                                                                                                                                                                                                                            |
| Status                           | One of the six statuses defined in the baseline. **“Verified” appears only with named test evidence.**                                                                                                                                                                                                      |
| Exc.                             | Exception ID from [security-exceptions-register.md](./security-exceptions-register.md) — the register is empty today.                                                                                                                                                                                       |
